=== Wolfi/Chainguard package advisories (samples/wolfi_openssl.advisories.yaml) ===
Format: Chainguard 'secfixes/advisories' YAML (schema-version 2.0.2),
NOT OpenVEX. One file per PACKAGE (not per image, not per CVE),
containing every advisory (CVE) ever filed against that package across
all its historical versions.

CORRECTION (post sixth-finding investigation, see ../06-chainguard-vex-investigation/RESULTS.md):
wolfictl's `vex` subcommand does NOT generate OpenVEX on demand from this data --
it is a dead no-op stub, dropped by Chainguard itself in commit 9364dfe9 (2023-06-07).
There is no on-demand OR static OpenVEX generation path for Wolfi/Chainguard container
images. The only real, live OpenVEX feed found anywhere in the Chainguard ecosystem is
for Chainguard Libraries (remediated PyPI/Java packages) at libraries.cgr.dev/openvex/v1/ --
a different product with no image concept at all.

Confirmed live today: packages.wolfi.dev/os/openvex.json, security.openvex.json, and
openvex/index.json all 404 -- no static per-image/per-package OpenVEX feed exists.
